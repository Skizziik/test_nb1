# Экономика и баланс v0.1

Источник цифр: `data/balance.json`. Этот же файл должен читать игровой клиент, чтобы баланс правился в одном месте.
Проверка: `tools/economy_sim/sim.py` (Monte Carlo, боты-игроки).

## 1. Валюты и ресурсы

| Ресурс | Откуда | Куда |
|---|---|---|
| Монеты | Оплата напитков, чаевые, цели дня | Улучшения, переезд, аренда, ингредиенты, зарплата |
| Рейтинг (звёзды) | Удовлетворённость гостей | Поток гостей, ворота на переезд |
| Дружба с постоянными | Их "свой" напиток, скорость | Рецепты, декор, истории (в симе пока не моделируется) |

Одна валюта сознательно: для MVP проще читать и балансить. Вторая валюта (например, редкие зёрна для эндгейма) только если понадобится сток.

## 2. Формулы

Все коэффициенты в `balance.json`.

**Поток гостей** (Пуассон, гостей/сек):

```
rate = arrivals_per_min(loc) / 60
     x (0.5 + 0.2 x stars)            # 1 звезда = x0.7, 5 звёзд = x1.5
     x decor.arrival_mult
     x event.arrival_mult
     x 1.35 в утренний раш (первая треть смены)
```

**Время приготовления:**

```
t = (drink.time_s + sum(mod.time_add_s))
    x grinder.mult x espresso.mult   (если кофе)
    x steamer.mult                   (если молочный)
    x ice.mult                       (если холодный)
    x skill_speed                    (игрок: 1.0 про, 1.4 новичок)
    + 3 сек на выдачу
```

**Уход гостя:** если ожидание до начала обслуживания > терпение x decor.patience_mult.

**Удовлетворённость** (0..1):

```
wait_score = 1 - 0.7 x wait / patience
sat = q_weight x quality + (1 - q_weight) x wait_score + loyalty_bonus
ушедший гость: sat = 0.1
ошибка в заказе: quality = 0.25, чаевых нет
```

**Цена и чаевые:**

```
price = (drink.price + mods) x menu_board.mult x location.price_mult
tip   = price x customer.tip_rate x tip_jar.mult x sat^2
profit_day = sum(price) + sum(tip) - sum(ingredient_cost) - rent - helper_wage
```

`sat^2` в чаевых специально: разница между "нормально" и "отлично" ощущается в кошельке.

**Рейтинг за день:**

```
day_score = 1 + 4 x weighted_mean(sat)    # критик весит x4
stars = 0.7 x stars + 0.3 x day_score
```

## 4. Симуляция: 720 ботов

Метод: 3 уровня навыка (casual, average, pro) x 6 стратегий покупок x 40 случайных сидов, 60 игровых дней каждый.

Стратегии:
- **saver**: ничего не покупает, копит только на переезд
- **cheapest**: всегда самое дешёвое доступное
- **speed**: сначала оборудование на скорость
- **decor**: сначала декор, меню и лояльность
- **balanced**: тратит не больше 35% кошелька за раз
- **random**: случайная доступная покупка

Все боты, кроме saver, откладывают часть денег на следующий переезд, как сделал бы живой игрок, видящий цель на карте.

### Выводы

1. **Темп в целом попадает в цель.** Средний игрок: 2-я локация на ~7 день, 3-я на ~23, финальная на ~39. Новичок отстаёт на ~6 дней к финалу, про опережает на ~4. Разрыв ~25%, это здоровый уровень: навык важен, но новичок не застревает.
2. **Без улучшений игра не проходится.** Saver не доходит до 4-й локации ни в одном из 120 прогонов: без оборудования уходы 21-25%, рейтинг застревает на ~3.0-3.5 и не пускает дальше. Это правильно, прокачка обязательна.
3. **Нет доминирующего пути прокачки.** Cheapest, speed, decor и random приходят к финалу почти в один день. Плюс: игрок не может "ошибиться" с выбором. Минус: выбор может ощущаться бессмысленным. Предложение: дать улучшениям разную идентичность (декор притягивает туристов и ценителей, скорость спасает от офисного раша), чтобы выбор зависел от локации.
4. **Ранний переезд наказывается.** Balanced переезжает раньше всех, но дальше отстаёт по рейтингу и доходу. В UI стоит предупреждать: "твоя кофемашина не вывезет поток на новой точке".
5. **Уходы слишком высокие.** 8-14% у нормальных стратегий в среднем, а в раш заметно выше. Цель: 4-7% для среднего игрока. Рычаги: мягкий старт раша, POS-планшет раньше, "успокоить гостя" (бесплатное печенье за небольшую плату), помощник уже на 1-й локации с урезанными возможностями.
6. **Нет стока денег после 4-й локации.** К 60 дню у сильных игроков в кошельке 10-18 тысяч без применения. Нужен эндгейм: франшиза, престиж, дорогая косметика, мини-игра обжарки.

### Что симуляция НЕ проверяет

Весёлость, читаемость мини-игр, ощущение раша. Боты моделируют игрока через скорость и точность, а не через реальный интерфейс. После MVP стоит собрать телеметрию живых игроков (время на напиток, частота ошибок) и подставить реальные значения в `SKILLS` симулятора.

## 5. Как пользоваться

```bash
python tools/economy_sim/sim.py --days 60 --seeds 40 --plots docs/balance --json docs/balance/summary.json
```

Процесс правки баланса: меняешь `data/balance.json`, гоняешь сим, сравниваешь таблицу с целями выше, коммитишь JSON и обновлённый отчёт вместе.
